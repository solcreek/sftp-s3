# AWS module

An OpenTofu / Terraform module that runs sftp-s3 on AWS, in one of two
shapes measured in [docs/deploy-aws.md](../../docs/deploy-aws.md):

- `compute = "ecs"` (default): 2 Fargate tasks (ARM64) in two AZs behind an
  NLB with one Elastic IP per AZ, at about $45–50 a month. Highly available;
  rolling deploys keep in-flight uploads for about 4–6 minutes.
- `compute = "ec2"`: one t4g.small with an Elastic IP and the container on
  port 22, at about $17 a month. A change replaces the instance, with about
  2 minutes of downtime; the IP stays.

Both shapes get the same base:

- **Network:** their own VPC with an S3 gateway endpoint and no NAT gateway,
  so upload traffic to S3 is free. With `create_bucket = true`, a bucket
  policy makes the gateway's role use that endpoint.
- **Credentials:** IAM roles only, no access keys.
- **Users and host key:** in SSM Parameter Store, read at start.
- **Host key:** generated by default.

## Use

```hcl
provider "aws" {
  region = "us-east-1" # the bucket's region
}

module "sftp" {
  source = "github.com/solcreek/sftp-s3//deploy/aws?ref=v0.1.0"

  bucket_name   = "my-sftp-uploads"
  allowed_cidrs = ["203.0.113.0/24"]
  users = [
    "alice:ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... alice@laptop",
    "bob:$2a$10$...", # sftp-s3 -hash-password
  ]
}

output "sftp_address" { value = module.sftp.sftp_address }
output "known_hosts" { value = module.sftp.known_hosts }
```

A runnable copy is in [examples/aws](../../examples/aws).

```sh
tofu init && tofu apply
tofu output -raw known_hosts >> ~/.ssh/known_hosts   # pin the host key
sftp alice@"$(tofu output -raw sftp_address)"
```

**Health checks.** The NLB checks the SFTP port over TCP; the module does
not set `SFTP_METRICS_ADDR`. On a deploy, ECS deregisters a task from the
target group before sending it SIGTERM, so a draining task gets no new
clients without an HTTP check. To scrape metrics, add
`SFTP_METRICS_ADDR` to the task's environment yourself and open that port
to your Prometheus only, never in `allowed_cidrs`
([Metrics and health](../../README.md#metrics-and-health)).

**Changes:** change `image`, `users` or settings and apply.

- **ECS:** gets a new task definition revision and rolls to it.
- **EC2:** the instance is replaced.

## Secrets and the state

By default the state holds:

- **`users`:** public keys and bcrypt hashes, which are not secret;
- **the generated host key:** which is secret.

Protect the state accordingly. To keep both out of it, set `users = null`
and `generate_host_key = false`. The module then creates placeholder
parameters and never touches their values; write them yourself:

```sh
aws ssm put-parameter --overwrite --type SecureString --name /sftp-s3/users    --value "$(cat users)"
aws ssm put-parameter --overwrite --type SecureString --name /sftp-s3/host-key --value "$(cat host_ed25519)"
```

Then restart the gateway:

- **ECS:** `aws ecs update-service --cluster sftp-s3 --service sftp-s3 --force-new-deployment`
- **EC2:** `systemctl restart sftp-s3` over SSM Session Manager

Until the parameters are set the gateway refuses to start.

## Using an existing bucket

Set `create_bucket = false`. The module then leaves the bucket's policy and
lifecycle untouched, because those resources replace the whole
configuration. Instead:

- merge `bucket_policy_statement` (an output) into the bucket policy;
- add an `AbortIncompleteMultipartUpload` lifecycle rule. A task killed
  mid-upload leaves parts behind.

## Inputs

| variable | default | notes |
|---|---|---|
| `bucket_name` | required | |
| `allowed_cidrs` | required | who may reach port 22 |
| `users` | `null` | `SFTP_USERS` entries, one per element; `null` = manage the parameter yourself |
| `compute` | `"ecs"` | or `"ec2"` |
| `image` | `ghcr.io/solcreek/sftp-s3:0.1` | any registry; private ECR images work too |
| `create_bucket` | `true` | `false`: use an existing bucket (see above) |
| `generate_host_key` | `true` | `false`: manage the parameter yourself |
| `s3_prefix` | `""` | every user lives under `<prefix><user>/` |
| `max_connections` | from memory | about 120 MiB per concurrent large upload: 3 per 512 MiB task, 14 on a t4g.small |
| `cross_zone_load_balancing` | `true` | off, connections from one client pile onto one AZ's task (measured) |
| `desired_count` | `2` | the NLB balances by flow hash, so one task's cap trips before the total does; leave headroom |
| `task_cpu` / `task_memory` | `256` / `512` | 0.25 vCPU uploaded at 113 MiB/s in-region |
| `instance_type` | `t4g.small` | Graviton (arm64) |
| `name` | `"sftp-s3"` | prefix for every resource |

Outputs:

- `sftp_address` and `public_ips`;
- `host_key_fingerprint` and `known_hosts`;
- `parameters`;
- `bucket_policy_statement`.

## Verified

2026-11-01 in ap-northeast-1 (OpenTofu 1.13, AWS provider 6.71), through
`examples/aws` with an image in a private ECR repository:

- **ECS:**
  - apply from scratch;
  - key and bcrypt logins checked against the `known_hosts` output;
  - adding a user rolled a new task definition revision, and the user could
    log in.
- **Switching to EC2:**
  - the same logins, with the same host key;
  - removing a user replaced the instance: the IP was kept, service resumed
    131 s after the apply started, and the removed user was refused.
- `tofu plan` showed no changes after each step.
